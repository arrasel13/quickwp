===============================================================================
                          NEXORA MANAGER - SETUP INSTRUCTIONS
===============================================================================

🚀 NEXORA MANAGER - WordPress Development Environment Desktop Application

This document provides complete instructions for running the project in
development mode (preview) and building it for production deployment.

===============================================================================
📋 PREREQUISITES
===============================================================================

Before running Nexora, ensure you have the following installed:

1. Node.js (version 16.x or higher)
   - Download from: https://nodejs.org/
   - Verify installation: node --version

2. Rust and Cargo
   - Install from: https://rustup.rs/
   - Verify installation: cargo --version

3. Xcode Command Line Tools (macOS only)
   - Install with: xcode-select --install
   - Required to link the Rust backend

NOT prerequisites (Nexora handles these itself):

- PHP, MySQL/MariaDB and WP-CLI are downloaded on demand the first time a
  site needs them, each verified against a pinned checksum. You do not
  install them yourself.

- Laravel Herd is optional. Nexora only reads Herd/Valet configuration for
  the "Import from Herd" tab and to spot port conflicts. It never edits or
  removes anything Herd owns, and Nexora runs fine with Herd absent.

===============================================================================
▶️ RUNNING THE PROJECT (DEV MODE / PREVIEW)
===============================================================================

All commands below run from the app directory, not the repo root:

   cd quickwp-manager

-------------------------------------------------------------------------------
ONE-TIME SETUP
-------------------------------------------------------------------------------

   npm install

That is all that is needed up front. Cargo fetches the Rust crates on the
first run of the app.

-------------------------------------------------------------------------------
THE PREVIEW: RUN THE REAL DESKTOP APP
-------------------------------------------------------------------------------

   npm run tauri dev

This is the way to see the UI as it actually behaves. It:

   - starts Vite on http://localhost:1420 (a fixed port -- it fails rather
     than sliding to another one, because Tauri is pointed at that address)
   - compiles the Rust backend
   - opens the "Nexora" window
   - watches src/ and hot-reloads the React UI

⏱️  Be patient the first time. The initial Rust compile takes several
    minutes on a cold target directory. Later runs start in seconds.

What reloads, and what does not:

   - Edit anything under src/ (React, Tailwind) -> the window updates almost
     immediately, no restart.
   - Edit anything under src-tauri/ (Rust) -> Tauri recompiles and relaunches
     the window by itself. Slower, but automatic.

DevTools: right-click inside the window -> "Inspect Element" for the console
and the DOM, exactly as in a browser.

-------------------------------------------------------------------------------
⚠️  THE BROWSER-ONLY ROUTE, AND ITS LIMIT
-------------------------------------------------------------------------------

   npm run dev          # then open http://localhost:1420

This serves the same React app in your normal browser, and it is genuinely
faster to iterate in. But understand what you are looking at:

   Every call to the backend goes through Tauri's invoke(), which only exists
   inside the app window. In a plain browser tab it throws, so any tab that
   reads real data shows its error state instead of its content -- the Sites
   tab, for instance, renders "Could not read your sites".

So use the browser only for pure layout and styling work on views that do not
depend on backend data. For anything involving sites, PHP versions, services
or HTTPS, use `npm run tauri dev`.

(`npm run preview` serves the built dist/ folder in a browser and has exactly
the same limitation.)

-------------------------------------------------------------------------------
SEEING THE "NO SITES YET" EMPTY STATE
-------------------------------------------------------------------------------

The Sites tab shows its empty state only when the backend reports zero sites.
There is no mock data behind it -- an empty list means you really have no
sites yet.

To check what you have, and to get back to empty:

   cd quickwp-manager/src-tauri
   cargo build -p nexora-cli          # build the CLI once

   # It is not on your PATH; run it from the target directory:
   ./target/debug/nexora site list      # every site, and whether it serves
   ./target/debug/nexora site delete <domain>

Or from inside the app: pick the site, then Actions -> "Delete site". Delete
means the same thing in both places. A site you LINKED (rather than created)
loses only Nexora's record of it -- your folder is left alone.

-------------------------------------------------------------------------------
FRONTEND CHECKS WITHOUT LAUNCHING ANYTHING
-------------------------------------------------------------------------------

   npx tsc --noEmit     # type-check the React code on its own
   npm run build        # type-check + produce dist/ (no Rust involved)

Both are quick, and worth running before a commit that touches src/.

===============================================================================
🏗️ PRODUCTION BUILD (FOR DEPLOYMENT)
===============================================================================

To build the application for production deployment:

1. Navigate to the project directory:
   cd quickwp-manager

2. Build for your current platform:
   npm run tauri build

   Alternative command:
   npm run tauri:build

3. Platform-specific builds:

   For macOS (Universal - Intel & Apple Silicon):
   npm run build:macos

   For Windows:
   npm run build:windows

   For Linux:
   npm run build:linux

   For all platforms (using custom script):
   npm run build:all
   or
   ./build.sh

===============================================================================
📦 BUILD OUTPUT LOCATIONS
===============================================================================

After building, you'll find the installation files in:

📁 Main build directory:
   src-tauri/target/release/bundle/

📁 Platform-specific locations:

🍎 macOS:
   - App Bundle: src-tauri/target/release/bundle/macos/Nexora.app
   - DMG Installer: src-tauri/target/release/bundle/dmg/Nexora_0.1.0_aarch64.dmg

🪟 Windows:
   - Executable: src-tauri/target/release/bundle/msi/Nexora_0.1.0_x64_en-US.msi
   - Setup File: src-tauri/target/release/bundle/nsis/Nexora_0.1.0_x64-setup.exe

🐧 Linux:
   - AppImage: src-tauri/target/release/bundle/appimage/nexora_0.1.0_amd64.AppImage
   - DEB Package: src-tauri/target/release/bundle/deb/nexora_0.1.0_amd64.deb

===============================================================================
📱 INSTALLATION INSTRUCTIONS
===============================================================================

🍎 macOS Installation:
1. Locate the .dmg file in the build output
2. Double-click the .dmg file to mount it
3. Drag "Nexora" to the Applications folder
4. Launch from Applications or Spotlight

🪟 Windows Installation:
1. Locate the .msi or .exe file in the build output
2. Right-click and select "Run as administrator"
3. Follow the installation wizard
4. Launch from Start Menu or Desktop shortcut

🐧 Linux Installation:
1. For AppImage:
   - Make executable: chmod +x nexora_0.1.0_amd64.AppImage
   - Run directly: ./nexora_0.1.0_amd64.AppImage

2. For DEB package:
   - Install: sudo dpkg -i nexora_0.1.0_amd64.deb
   - Launch from applications menu

===============================================================================
🛠️ TROUBLESHOOTING
===============================================================================

Common Issues and Solutions:

1. "Command not found: tauri"
   Solution: Install Tauri CLI globally
   npm install -g @tauri-apps/cli

2. "Rust not found" error
   Solution: Install Rust from https://rustup.rs/

3. Build fails on macOS
   Solution: Install Xcode Command Line Tools
   xcode-select --install

4. Windows build issues
   Solution: Install Microsoft C++ Build Tools
   https://visualstudio.microsoft.com/visual-cpp-build-tools/

5. "Port 1420 is already in use"
   Solution: Another `npm run dev` or `npm run tauri dev` is still running.
   The port is fixed on purpose, so close the other one rather than
   changing it.  lsof -ti:1420 | xargs kill

6. The Sites tab says "Could not read your sites"
   Solution: You are almost certainly viewing it in a plain browser tab via
   `npm run dev`. The backend is only reachable inside the app window --
   use `npm run tauri dev`.

🔄 DEVELOPMENT WORKFLOW
===============================================================================

Recommended development workflow:

1. Start development server: npm run tauri dev
2. Make changes to React components in src/
3. Changes auto-reload in the desktop app
4. Test Rust backend changes in src-tauri/src/
5. Build for testing: npm run tauri build --debug
6. Final production build: npm run tauri build
